## Now

### Step 18b: Evaluation (on `feature/evaluation`)
- [x] Data source decided: synthetic incidents modelled on published attack patterns (ADR-53)
- [x] Development set: 60 incidents, 30 attacks and 30 harmless, with hard cases both ways (`agent/tests/evaluation_set.py`)
- [x] First run, before any change: 22 of 30 attacks caught (73%), 6 of 30 false alarms (20%); both targets missed
- [x] General fixes for the gaps it showed: card/bank-detail requests, threats of arrest, secrecy, password spraying over many addresses, wider urgency/impersonation/credential wording, "we never ask for your OTP" no longer counted as a request. Development set after: 27 of 30 (90%), 4 of 30 (13%)
- [x] Held-out set written after the fixes (40 incidents, `evaluation_heldout.py`) and run once: **12 of 20 attacks caught (60%), 1 of 20 false alarms (5%)**
- [x] `docs/EVALUATION.md` generated by `scripts/evaluate.py`; CI fails if it stops matching the agent (the targets are reported, not asserted: ADR-53)
- [x] Tests: 656 agent tests pass; 6 mutation checks, all caught. A first `--model` run showed the rule-engine pass quietly using the model; fixed, with a guard and a test
- [x] Mohit's run with the local AI model (qwen3:8b; 92 of 100 led by the model): held-out 20 of 20 caught, 13 of 20 false alarms; development 30 of 30, 16 of 30. The model calls most incidents with any finding "suspicious" (recorded in `testdata/evaluation-model-run.json`)
